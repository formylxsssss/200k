# 单道 400 kS/s 自容式水听器固件总体设计

版本：V0.1  
工程：single_channel_device  
目标：先搭建可编译、可扩展的普通业务框架，后续逐步补齐 W5500 Socket、FATFS、ADS127L11 寄存器细节和上位机协议。

## 1. 设计目标

本系统按自容式水听器思路设计，核心能力包括：

- 支持最大 400 kS/s 采样能力，运行时支持可变采样率。
- 支持采样精度配置，当前框架定义 16 bit、24 bit、32 bit 三种输出格式；硬件 ADC 原始输出以 ADS127L11 24 bit 为核心。
- 支持模拟前端增益/量程配置。根据当前硬件设计，模拟前端实际可控项主要是 ADG704 衰减档位和 PB6-PB9 控制位；框架中以 0 dB、-10 dB、-20 dB、-30 dB 四档作为硬件增益/量程基础。
- 支持上位机授时，授时后进入可信时间状态，用于任务表调度和数据文件命名。
- 支持 TCP Server 模式，设备作为 TCP 从机/服务端，上位机作为客户端连接并下发指令。
- 支持实时传输模式：采样数据通过网口实时发送，不写 SD 卡。
- 支持自存储模式：
  - 立即采集存储：收到开始指令后，按当前配置开始采集并持续写入 SD 卡。
  - 任务表模式：授时后，按任务表指定时间、间隔、持续时间、采样率、采样精度、增益等参数自动采集并写入 SD 卡。
- 支持 PC13 低电平触发采集：上位机预先配置采样率、采样精度、增益、持续时间和触发后动作，PC13 被外部光耦电路拉低后可实时上传或写入 SD 卡。
- 支持 4 张 TF/SD 卡自检、容量统计、卡槽状态上报，最大按 4 x 2 TB = 8 TB 总容量设计。
- 支持采集结束后通过网口读取 SD 卡中的文件，同时保证拔卡后也能在电脑读卡器中直接复制数据。

## 2. 总体架构

固件分为四层：

1. 硬件抽象层  
   GPIO、SPI1、SDMMC1、SDMMC2、TIM3、ADS127L11、TF 卡槽选择、W5500 底层读写。

2. 服务层  
   时间服务、配置服务、TCP 服务、存储管理、实时流服务、任务调度服务。

3. 业务控制层  
   统一处理运行模式切换、上位机命令、采集启停、数据路由和错误状态。

4. 数据格式层  
   负责采集文件头、数据块、索引文件、任务信息、设备信息和异常记录。

当前代码框架中新增/规划模块如下：

- `app_controller`：系统业务入口，管理设备模式和主循环任务。
- `system_config`：统一定义采样率、采样精度、增益、运行模式、任务参数等类型。
- `time_service`：上位机授时、系统时间递增、时间有效性判断。
- `tcp_service`：TCP Server 框架，负责接收命令和发送响应/数据。
- `command_protocol`：解析上位机命令，输出业务动作。
- `storage_manager`：SD 卡自检、容量统计、卡槽状态、文件路径规划。
- `storage_recorder`：自存储会话管理，负责写入数据文件和元数据。
- `task_scheduler`：任务表管理，到时启动采集或周期性采集。
- `stream_service`：实时传输模式的数据发送出口。

## 3. 运行模式

系统定义以下运行模式：

- `IDLE`：空闲，仅响应查询/配置/授时等指令。
- `REALTIME_STREAM`：实时传输模式，采样数据只通过 TCP 发送，不写 SD 卡。
- `SELF_STORAGE_IMMEDIATE`：收到开始指令后立即写卡。
- `SELF_STORAGE_SCHEDULED`：按任务表自动采集写卡。
- `TRIGGER_ARMED`：PC13 低电平触发已布防，等待外部触发。
- `REALTIME_TRIGGERED`：PC13 触发后的定时实时上传采集。
- `STORAGE_TRIGGERED`：PC13 触发后的定时自存储采集。
- `FILE_SERVICE`：文件服务状态，用于上位机读取 SD 卡目录和文件内容。
- `ERROR`：严重错误状态，保留日志和错误码，等待复位或上位机处理。

数据路由原则：

- 实时传输模式：ADS127L11 -> RAM 环形缓冲 -> TCP 数据发送。
- 自存储模式：ADS127L11 -> RAM 环形缓冲 -> SD 数据文件。
- 低电平触发实时上传：PC13 -> 触发状态机 -> ADS127L11 -> RAM 环形缓冲 -> TCP 数据发送。
- 低电平触发写卡：PC13 -> 触发状态机 -> ADS127L11 -> RAM 环形缓冲 -> SD 数据文件。
- 后续可扩展双路：低速监控数据实时传，高速原始数据本地存。

## 4. TCP Server 和上位机指令

设备作为 TCP Server，建议默认监听端口：

- 控制端口：5000
- 数据端口：5001
- 文件服务端口：5002

当前框架先定义单服务入口，后续可按端口拆分。

建议指令分组：

- 设备查询：查询固件版本、设备序列号、硬件状态、运行模式。
- 时间管理：上位机授时、读取当前设备时间、查询时间有效性。
- 配置管理：设置采样率、采样精度、增益/衰减、采集时长、存储策略。
- SD 管理：查询插卡数量、卡槽号、容量、剩余容量、当前写入卡。
- 采集控制：开始实时传输、停止实时传输、开始立即自存储、停止自存储。
- 任务表：添加任务、删除任务、查询任务、清空任务表、启用/禁用任务表。
- 文件服务：列目录、读文件、删除文件、读取索引、查询某时间段数据。
- 低电平触发：设置触发采集参数和触发后动作、启动触发模式、停止触发采集、查询触发状态。
- 维护诊断：读取日志、读取错误码、执行自检、软复位。

协议格式建议采用二进制帧：

| 字段 | 长度 | 说明 |
|---|---:|---|
| magic | 2 | 固定 0xA5 0x5A |
| version | 1 | 协议版本 |
| command | 1 | 命令字 |
| sequence | 2 | 帧序号 |
| length | 2 | payload 长度 |
| payload | N | 负载 |
| crc32 | 4 | 帧校验 |

当前代码先提供命令分发框架，CRC 和完整拆包可在 W5500 Socket 可用后补齐。

## 5. 采样参数和硬件约束

采样率：

- 最小值建议：1 kS/s
- 默认值：200 kS/s
- 最大值：400 kS/s

采样精度：

- 16 bit：便于低带宽实时传输，数据由 24 bit 原始值右移或缩放得到。
- 24 bit：ADC 原始精度，推荐用于自存储。
- 32 bit：以 int32 保存 24 bit 符号扩展值，便于 MCU 内部处理和对齐。

增益/量程：

- 当前硬件看到的是模拟衰减档位，不是可编程放大器。
- 支持档位：0 dB、-10 dB、-20 dB、-30 dB。
- PB6-PB9 保留为量程/开关控制位，具体含义后续需结合原理图和实测标定固化。

需要补充考虑：

- 每个采样率对应 ADS127L11 寄存器、外部 MCLK、数字滤波配置关系。
- 每个增益/衰减档位对应满量程输入、电压换算系数和水听器灵敏度标定。
- 实时传输模式下，400 kS/s x 24 bit 约 1.2 MB/s，TCP 和上位机接收端必须持续消费，否则设备需丢包统计或降速。

## 6. SD 卡和文件系统设计

硬件有 4 个卡槽，分两组 SDMMC：

- SDMMC1 通过切换芯片连接 TF1/TF2。
- SDMMC2 通过切换芯片连接 TF3/TF4。

开机自检流程：

1. 关闭所有卡槽电源。
2. 依次选择 TF1-TF4。
3. 打开对应卡槽电源，尝试 SD 初始化。
4. 读取卡容量、块大小、可用空间。
5. 记录卡槽状态并上报上位机。
6. 按策略选择当前写入卡。

容量设计：

- 单卡容量按 2 TB 设计，变量必须使用 64 bit。
- 总容量按 8 TB 设计。
- 文件大小建议分片，避免单文件过大导致 FAT/exFAT 管理困难。

目录结构建议：

```text
/HYDROPHONE
  /DEVICE
    device.json
    calibration.json
  /INDEX
    index.csv
    task_index.csv
  /DATA
    /YYYYMMDD
      /RUN_YYYYMMDD_HHMMSS_mmm_RATEHz_MANUAL_xxxxxx
      /RUN_YYYYMMDD_HHMMSS_mmm_RATEHz_TASK_xxxxxx
      /RUN_YYYYMMDD_HHMMSS_mmm_RATEHz_TRIG_xxxxxx
        meta.json
        data_000001.bin
        data_000002.bin
        event.log
```

数据文件需要支持两种读取方式：

- 网口读取：上位机按索引查询时间段，再读取对应文件块。
- 拔卡读取：电脑直接打开 `meta.json`、`index.csv` 和 `data_xxxxxx.bin`。

每次采集至少保存：

- 设备序列号、固件版本。
- 采集开始/结束时间。
- 采样率、采样精度、增益/衰减、量程控制位。
- 存储模式：立即存储或任务表。
- 任务 ID。
- 卡槽号、文件序号。
- 数据格式、端序、CRC/校验。
- 异常统计：丢样、写卡失败、网络断开、电压异常等。

## 7. 任务表模式

任务表必须依赖有效授时。没有授时，不允许启动绝对时间任务。

任务类型：

- 单次任务：到指定 UTC 时间开始，采集指定时长。
- 周期任务：首次开始时间 + 间隔 + 持续时长 + 次数。
- 长期任务：按间隔持续执行，直到上位机取消或存储空间不足。

任务参数包括：

- task_id
- enabled
- start_time_ms
- interval_ms
- duration_ms
- repeat_count
- sample_rate_hz
- precision_bits
- gain/attenuation
- storage_policy

任务执行时，应将任务配置复制进采集元数据，确保事后能明确某段数据是什么模式、什么参数采集的。

## 8. PC13 低电平触发模式

原理图中 PC13 触发输入位于 `W5500_guangzi` 图左侧：PC13 通过 `R8 4.7K` 上拉到 `3V3`，外部输入经光耦 `U8` 和三极管 `Q7` 后下拉 PC13。因此固件只按低电平触发处理。

触发采集流程：

1. 上位机通过 `TRIG_CONFIG` 设置采样率、采样精度、增益、持续时间、输出方式和单次/连续触发。
2. 上位机发送 `TRIG_ARM`，设备进入 `TRIGGER_ARMED`。
3. PC13 低电平保持超过去抖时间后，设备按输出方式进入 `REALTIME_TRIGGERED` 或 `STORAGE_TRIGGERED`。
4. 选择实时上传时，采集数据通过 TCP 数据端口发送；选择写卡时，采集数据按现有 SD 卡顺位写入机制保存。
5. 持续时间到达后自动停止当前触发采集。单次模式回到 `IDLE`；连续模式等待 PC13 恢复高电平后回到 `TRIGGER_ARMED`，再等待下一次低电平。
6. 连续模式不对采集期间的新触发排队，PC13 持续低电平时不会连续重复启动。

触发写卡时，采集文件仍保存在：

```text
/HYDROPHONE/DATA/RUN_20260915_143020_123_200000Hz_TRIG_000001/
  meta.txt
  data.bin
  segment_end.txt
  run_end.txt
```

其中 `meta.txt` 中记录 `source=TRIGGER`，用于和手动自存储、任务表采集区分；`segment_end.txt` 和 `run_end.txt` 分别保存卡段结束信息与整次采集的最终统计。

## 9. 异常和可靠性补充

建议补充以下机制：

- 掉电保护：数据文件分块写入，每块带头和 CRC；meta 文件先写临时文件，结束后改名。
- 写卡失败处理：自动切换到下一张可用卡，并在索引中记录切卡事件。
- 网络断开处理：实时模式下允许丢弃数据并统计；自存储模式不受网络影响。
- 时间漂移：授时后记录授时源和本地 tick，长时间运行需支持重新授时。
- 校准信息：每个设备/通道保存水听器灵敏度、模拟前端衰减标定、ADC 参考电压。
- 文件索引恢复：开机扫描未正常结束的 RUN 目录，标记为 interrupted。
- SD 卡热插拔：硬件若没有检测脚，则只能通过定期低频重扫或上位机触发重扫。
- 存储空间水位：剩余容量低于阈值时提前报警，避免采集到一半才失败。
- 版本兼容：协议帧、数据文件、meta 文件都需要版本号。
- 安全控制：如设备部署在现场，建议至少有简单会话令牌，避免误连接误操作。
